# Prompt Lab — Build It. Test It. Own It.

**Vibe Coding for Entrepreneurs · Days 1–2 · November 9–10, 2026**

This is a free, offline, single-file interactive lesson that helps beginner entrepreneurs turn a *fictional* business problem into a structured AI coding prompt with acceptance checks. There is no login, backend, third-party JavaScript, payment processing, storage, or network activity.

## Start

1. Download `day1-prompt-builder.html`.
2. Double-click it to open it in your browser. You do not need a code editor or API key.
3. Begin with the prefilled **Electric Bloom Studio** classroom example, or replace it with other *fictional* sample details.
4. Select **Build my AI prompt**.
5. Review the generated prompt in the right-hand panel. Use **Copy prompt** if your browser grants clipboard permission or **Download .txt** to save your work locally.
6. Paste the prompt into an AI coding tool if you choose. Ask it for a plan first, verify its assumptions, and approve each change before deployment.
7. Test the work against the generated checklist. Share only your observations and fictional project screenshots with the community.

## Safety and transparency

- Input text is held in the page's current form only; the page performs **no requests, database writes, cookies, analytics, or local storage**.
- It is a prompt-writing exercise, not a working AI integration. No AI model is called.
- For browser clipboard access, some browsers restrict `file://` pages; the `Download .txt` feature is a fallback.
- Do **not** enter real customer messages, account passwords, API keys, financial or medical details, or copyrighted third-party source code.
- Generated prompts include review gates and explicitly prohibit actual customer information, payments, trackers, and hidden integrations.
- The provided Electric Bloom Studio website is a **fictional classroom demonstration**, not a live business contact service.

## Testing performed

Automated Chromium / Playwright tests checked default prompt creation, custom-text escaping (no script insertion), whitespace-only required fields, restoring demo values, clearing inputs, `.txt` download, field labels, no network requests, no JavaScript exceptions, and no horizontal overflow at six viewport widths (320, 360, 375, 390, 768, 1440 px). This does **not** establish exhaustive accessibility, browser compatibility, or security certification.
